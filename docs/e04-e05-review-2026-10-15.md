# E04 / E05 repeat code review, 2026-10-15

The review covers the E04 and E05 draft source trees, including inherited
Generation/Storage lifecycle behavior, Projects releases, Core preparation,
shared contracts, events and the internal stand. Independent reviewers
inspected separate domains; fixes received another independent review.
Later implementation and closure reviews used GPT-6.1 Sol High at the user's
request. Merge, releases and formal milestone acceptance remain separate.

| Finding | Impact and repair | Regression evidence |
| --- | --- | --- |
| P1: Storage accepted an incomplete or ambiguous owner response | Access/publication could trust a valid JSON prefix. A malformed `absent` decision could release a pending pin and delete its snapshot. Read the complete bounded body and use the strict shared DTO decoder before trusting a decision. Applies to E04 and E05. | Fifteen malformed HTTP decision cases failed before the fix. Actual PostgreSQL/S3 GC deleted the aged protected snapshot on the old code; repaired code retains it with an unresolved pin. Valid responses still work. |
| P2: E05 release withdrawal during metadata preflight still admitted a job | After resolving a release, recheck current publication and rights against the exact actor/scope/release/descriptor immediately before `Store.Admit`. Denial is safe 409; uncertainty is safe 503. Working selections and existing receipt replay preserve their behavior. | Paused metadata tests withdraw/revoke/fail the dependency after resolution. Denied requests leave zero jobs, receipts, reservations, input-resource rows, pin-acquire rows, workflow starts or Storage pin calls. Positive, empty-resource, working and replay controls pass. |
| P2: E05 source could own the reserved input root | Shared Core technical validation now rejects a `.leafrun-input` file or empty/nonempty directory before revision registration or release creation. Execution retains its own guard. | Core tests cover both public validation paths and allowed similar/nested names. Projects HTTP registration rejects with a stable field diagnostic before durable revision/release or pins. |
| P2: Valid schema bytes were inflated by intermediate/wire encoding | Strict JSON decoding now applies its cap to actual input bytes. Core retains independently owned validated schema bytes. Form encodes metadata normally and appends compact validated schema tokens, preserving Unicode and the existing 4 MiB closure / 12 MiB response caps. Canonical normalization and fingerprints remain unchanged. The shared decode repair applies to both stages; the form repair is E05. | Red tests found large single schemas rejected at registration and a valid published aggregate closure rejected by Form with 413. The real client now accepts HTML, U+2028/U+2029 and aggregate closures, including 4,140,099 source bytes yielding an 8,280,673-byte response. Literal backslash escapes, quotes, malformed raw JSON, numeric tokens and byte caps are covered. |
| P3: E04 treated generic HTTP 410 as typed pin expiry | Only `409 pin_expired` may rotate an acquisition key. Other failures preserve the durable identity. E05 already had this rule. Current Storage snapshots have no TTL, so this is a protocol robustness repair rather than an ordinary snapshot-expiry incident. | Red tests reproduced rotation on generic 410; typed-expiry and stable-identity regressions pass. |

The final release check is a point-in-time authorization check. It closes the
observed preflight window without claiming an atomic transaction across
Projects and Generation databases.

Changed production surfaces are Storage `owner.go`, Contracts `jsonvalue/v1`,
Core project validation/schema resources, Projects form serialization and
Generation admission. Outbox/inbox, GC eligibility, fixed PDF expiry,
publication fencing and the renderer sandbox were inspected; no additional
confirmed defects were found in those reviewed paths.

Full native tests, vet and build passed for the changed repositories, including
real PostgreSQL/S3/Temporal and Typst checks. The initial host stand test found
stopped development fixture containers after the host restart; those owned
fixtures were restarted before stand requalification. No unrelated services or
volumes were changed. Exact-ref hosted qualification, Linux race checks and
downloaded sanitized evidence are tracked in the related draft PRs; this review
requires fresh qualification at its updated source pins.
